# Key Design Decisions

This is a short summary of the main decisions behind the MediShield Multi-Agent Document Intake System. Each one has a full record (context, alternatives, consequences) in `docs/adr.md`.

| # | Decision | Why | Record |
| --- | --- | --- | --- |
| 1 | **The decision is made by deterministic code, not by an LLM.** A pure function applies four ordered rules: R1 agent errors or confidence below 0.6 escalate; R2 a fraud score of 0.30 or higher escalates; R3 failed KYC, an uncovered claim or an invalid schema rejects; R4 approves. An LLM only writes the justification text afterwards, and the code asserts it cannot change the decision. | Decisions about claims must be reproducible, explainable and testable. The rule trace lists every rule with its inputs. | ADR-003, spec 7.8 |
| 2 | **Agent failures are data, not crashes.** A failed agent returns an ERROR result, the pipeline continues, and rule R1 escalates the case to a human. Only infrastructure failures mark a case FAILED. | One flaky model call must not lose a case, and every failure leaves an audit trail. | ADR-002, spec 6.2 |
| 3 | **A LangGraph state machine with parallel branches.** Classify and OCR run first; KYC and Claims run in parallel; Policy runs after Claims; Fraud runs after they join; the orchestrator decides last. | The dependencies are explicit and testable, and parallel work cuts latency. | ADR-002 |
| 4 | **Provider abstraction with a stub mode.** All model calls go through one gateway. `stub` replays recorded fixtures for tests and development, and `groq` (also optional Anthropic and OpenAI) is used for the real run. Models: `openai/gpt-oss-120b` for text and `qwen/qwen3.8-27b` for vision. | Tests run offline and are repeatable, and the provider can change without touching agent code. | ADR-001 |
| 5 | **Tiered OCR.** The PDF text layer first, then Tesseract, then a vision model only when needed, merged field by field by confidence, with invalid values dropped. | The vision model is the slowest and most expensive step, so it runs only when the cheaper tiers are not confident. | ADR-007 |
| 6 | **Policy coverage uses deterministic exclusions first, then grounded retrieval.** A code is checked against the policy's excluded CPT ranges (no LLM). Otherwise Qdrant hybrid search (dense and sparse) retrieves clauses, and the model must cite text that is found verbatim in a retrieved clause. If it cannot, the answer is "unknown" and the case escalates. | Coverage answers must be grounded in policy text. A cross-encoder score proved unusable as an evidence gate (relevant and irrelevant clauses overlapped), so citation verification is the gate instead. | ADR-006, ADR-015 |
| 7 | **Fraud scoring is rules and statistics, not an LLM.** Ten detectors (duplicate claim, frequency spike, billing outlier, amount outlier, code mismatch, tamper signal, identity mismatch, near-threshold amount, date conflict, 30-day readmission) combine through a noisy-OR formula, rounded to four decimals. | The score is explainable, and each detector records its evidence. | ADR-008 |
| 8 | **Append-only audit log and immutable raw documents.** Every node start, end and decision is recorded. Overrides add a new record and never change the original decision. Raw files live in object storage by checksum. | Traceability for a regulated domain, and reruns never destroy history. | ADR-005, ADR-009 |
| 9 | **Reference date comes from the case, not the wall clock.** Expiry and recency checks use `cases.received_at`. The evaluation runner may set it from the dataset's reference date, and that override is refused in production. | A 2025-dated dataset stays valid when evaluated later, and production behaviour is unchanged. | ADR-013 |
| 10 | **Supporting documents and amendments have explicit rules.** Discharge summaries and prescriptions get no coverage decision (they are accepted or rejected on identity and completeness). Policy amendments always escalate for human confirmation unless KYC fails. | These document types carry no claim to check against coverage. The product owner confirmed both rules. | ADR-014 |
| 11 | **Security by default.** Argon2 password hashing, short-lived pinned-algorithm JWTs, role-based access (reviewer, supervisor, auditor, admin), a scoped service token for uploads, rate limits, a PHI log-redaction filter on all loggers, and in the web app a JWT in an httpOnly cookie that browser code cannot read. | Medical data needs least-privilege access and no PHI in logs or browser storage. | ADR-010 |
| 12 | **Synthetic data with a frozen dev/holdout split.** 238 fictional documents in 46 patient clusters (dev 25 clusters, holdout 21). Tuning uses dev only, and holdout is run once for the final numbers. | No real PHI, and honest evaluation numbers. | ADR-012 |
